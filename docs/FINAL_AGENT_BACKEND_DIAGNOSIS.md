## A. Architecture verification

The signed pull-request webhook in `backend/api/webhooks.py` checks the event, installation and automation policy. The manual trigger in `backend/api/installations.py` validates repository access and resolves the PR head. These paths enqueue a PostgreSQL review. Event deduplication and an explicit rerun have distinct semantics.

`backend/worker.py::main/run_next` runs a bounded child, acquires the database advisory lock, recovers abandoned work, skips superseded queued automatic reviews and services due delivery or pending analysis. `backend/services/review_service.py::start_review/_execute_graph_and_persist` and `backend/tools/workspace.py` prepare a checkout and merge-base diff tied to the reviewed head. The initial graph state carries PR metadata, changed paths, workspace, installation and standards version. Specialists inspect changed lines or overlapping symbols in that workspace. Test discovery also reads repository test files.

`backend/agents/supervisor.py::build_supervisor_graph/_fan_out` uses four LangGraph `Send` branches. The supervisor makes no model-routing call. Each branch writes its own keys into the reducers in `backend/agents/state.py`. The graph joins at `_aggregate`. The separate `backend/services/report_builder.py::aggregate` builds and ranks the actual findings. `review_service.py::_persist_findings/_persist_agent_runs` saves results, coverage and raw scanner evidence. The saved Markdown and delivery state feed a separate GitHub publication step. `backend/api/reviews.py` exposes saved review details and reports to the cookie-authenticated frontend.

## C. Quality root cause and skipped-check classification

`backend/agents/quality_agent.py::run` builds a per-batch retrieval query. On a retrieval exception or empty result it records a limitation and continues **before** `_discover_verified`. On success, `_discover_verified` calls `backend/agents/quality_rules.py::supported_rules` on just those passages. Consequently a readable changed file and an executable AST predicate are insufficient to run the corresponding check. A semantically unrelated but nonempty result can pass the context check, invoke enrichment, yield zero findings and leave coverage complete. The GitHub report inherits the agent's outcome and coverage. Changing its wording alone cannot restore the lost analysis.

| Requested classification | Diagnostic conclusion |

## D. Coding standards audit

`backend/rag/standards/python_coding_standards.md` covers naming, function length, complexity, arity, error handling, imports, annotations and docstrings. `backend/rag/ingest.py` chunks Markdown at section separators, uses content-derived IDs, creates versioned collections and updates the active default pointer. Installation upload/reset in `backend/api/standards.py` controls the installation pointer. `backend/rag/retriever.py::_get_collection` prefers an explicit version, otherwise resolves the applicable installation/default collection. Actual temporary Chroma queries against the default, with and without explicit pinning, each returned three passages yielding limits 40 and 5. A pinned one-rule custom collection returned 60. Unrelated material and a missing pin both yielded no usable passages. Availability failures were injected at the agent boundary. No active standards were changed.

| Proposed baseline category | Executable today | Advisory today or future implementation |
|---|---|---|
| Function design, length and arity | Python logic lines and positional parameters with explicit rules. JS/TS function length for the parser's supported exports and a language-applicable rule. | Keep Python defaults at 40 logic lines and five positional parameters. Define counting and exceptions. Complexity thresholds need an implemented Quality predicate. |
| Names, readability, modularity, duplication, maintainability | No general conformance checker in Quality. | Cite concise guidance on names, cohesion and repeated logic. Deterministic clone detection and cross-module architecture checks require additional work. |
| Types and language conventions | Python future-annotations import predicate exists. Its packaged instruction is currently lost by parsing. | Separate Python annotation conventions from TS guidance. General type safety needs type checking or a new predicate. |
| Error handling, resources, validation and secure coding | Dedicated scanners cover their individual rules. | Cite explicit rules for narrow exceptions, context managers and validating boundaries. Avoid presenting advisory reasoning as scanner evidence. |
| Dependencies and testability | Test Gaps checks direct static references in its supported languages. | Dependency auditing, executed branch coverage and behavioral correctness require independent evidence. Guidance can recommend isolating dependencies and testing failure paths. |
| Documentation | Python public symbol/parameter checks and limited frontend JSDoc consistency belong to Documentation. | Use explicit examples for interface changes, parameters, returns and exceptions. Python docstring conventions do not apply to TypeScript. |

Give each enforceable rule a stable ID, language, value, unit, exception and source/version. Keep the simple default policy available before vector retrieval and ensure its text agrees with the executable definition. Use retrieved passages for cited advice. Explicit custom values override only their matching defaults. Conflicting or inaccessible custom policies require a reported limitation on the affected verdict. Measurements and other independently resolved checks can still run. No global threshold relaxation, reindexing of live installations, model training or new scanner is justified by the reproduction. Python convention references are [PEP 8](https://peps.python.org/pep-0008/) and [PEP 257](https://peps.python.org/pep-0257/).

## F. Worker and provider reliability

* **Ownership and recovery.** A PostgreSQL advisory lock (73194201), transition to running, heartbeat, attempt count and stale-row handling guard execution. The parent bounds the child and terminates it on deadline or interruption. The oldest eligible pending row is claimed after due delivery work. Multiple queued automatic events can be superseded. A superseded review has its own terminal status.
* **Resume.** `backend/services/agent_checkpoints.py::AgentCheckpoints` stores successful specialist outputs against a review/fingerprint and separately keys Quality batches. Failed outcomes are eligible for retry. Finding and agent-run persistence replaces rows for the same review. Reusing the same review ID does not append another copy. Corrected policy semantics must invalidate incompatible old checkpoints.
* **Publication.** Markdown is saved with the analysis before delivery. `review_service.py::deliver_report` and bot publication/reconciliation use the review marker, bot identity and head checks. Delivery has separate retries. Tests exercise mocked GitHub publication; historical posted status is available for two reference rows. A fresh remote crash between publish and acknowledgement was outside this diagnosis.
* **Provider.** The effective local provider was Groq with `openai/gpt-oss-120b`; the source default is `openai/gpt-oss-20b`. Effective concurrency was one, configured retry count three, review attempts two, and the optional request ceiling unset. `backend/tools/llm_client.py` owns request admission, pacing, quota/backoff and timeout handling. The SDK's independent retries are disabled. A configured attempt budget counts actual sends, including retries. `backend/tools/review_budget.py` prioritizes required Security/Quality work ahead of optional drafts. The client uses the stages' own instructions, with downstream fingerprint, passage, AST and draft validation. Repository text and generated suggestions remain untrusted. No live prompt-injection resistance claim follows from these gates.
* **Expected calls.** Before retries, count one per nonempty Security triage batch, one per applicable Quality enrichment batch, and up to one per selected Test Gap or Documentation draft target. Security packs at most eight detections and 5,000 serialized characters per batch, up to 20 batches. Test and Doc cap draft targets at 10 and 15 respectively. Empty batches, unavailable context, checkpoints, deadline and optional-draft admission change the count. The tiny proposed fixture targets four first sends. Existing #89 acceptance recorded 19 successful sends and zero retries in that run. #90's progress events do not give a send count. Avoid sending a Quality request for a batch without applicable advisory context and reuse valid checkpoints. No budget increase is needed.
