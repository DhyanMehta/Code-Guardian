# CodeGuardian AI frontend audit

**23 November 2026 · Findings only · Source snapshot `dc9b6af`**

The highest-impact redesign decision is what the product invites someone to do after automation finishes. On the open PR, review #79 already covers the current commit and has 16 reported findings. Opening that evidence is a small link. The filled button creates another review. The same distinction matters in analytics. Nine completed reviews are a real outcome, while zero of ten reviews meet the server’s definition of fully recorded coverage. A user should be able to read both facts accurately at a glance.

### CG-UX-001 · The primary PR action creates another review · High

**Evidence — S2, L, C.** PR #1 shows “Review #79 · Completed”, matching SHA, 16 findings and posted delivery. The filled control is “Run a new review”. The review-status link opens the stored result. The button POSTs to the manual trigger, which reads the current PR head and creates a pending review row. The captured `auto` badge describes current installation policy. It does not establish the origin of review #79. Keep intentional reruns as a distinct secondary write. For active, stale, absent and unresolved reviews use the state-specific actions below.
